# 0014: A Claude Code session stopped for being idle is marked ended with reason idle, from Claude Code's daemon log

**Date:** 2026-10-01
**Status:** Accepted

## Context
Claude Code stops a background session by itself once it has been idle for an hour (60 seconds when the machine is short of memory), and runs no `SessionEnd` hook when it does (observed three times, 2.1.285). So Porch showed such a session as `gone`, the same as one that was killed or crashed, and decision 0013's aim of telling a clean stop from a death was not met for it. Sous chef needs the difference: it should resume a session Claude Code stopped for being idle and report one that died (TRV-1152, TRV-1158).

Claude Code's daemon writes a line to `daemon.log` in its folder when it stops a session this way, `bg retire <short id>: <cause>, idle <N>m`, about 90 ms before the process exits. A killed or crashed session gets no such line. The listing (`claude agents --json --all`) and the job file look the same for both, so they do not help. The log rotates to `daemon.log.1` and old logs are deleted, so the line does not stay there for ever. Its format is not documented.

## Decision
- An idle-stopped Claude Code session shows as `ended`, with `endReason: "idle"`, `since` the time on the retire line, and Claude Code's cause in `detail.idleStop` (`{ cause, idleMinutes, lowMemory }`). `gone` keeps meaning the session died. Every `bg retire` line counts, whatever its cause.
- The first look of any kind (`list`, `watch`, `observe`, `deliver`) that finds the line marks the record ended in its `inside` part, with the fields `SessionEnd` would have written (`status: ended`, `endedAt` the retire time, `endReason: idle`) plus `data.idleStop`, through `RecordStore.markInsideEnded`, which writes only when the record exists and has not ended, under the record's lock. Once marked, the answer no longer depends on the log, and every part of the ended handling decision 0013 built applies unchanged: deliver says not-running, the record is removed 24 hours after `endedAt`, a resume's `SessionStart` starts it again, and late hooks are ignored.
- **This amends decision 0001** (each adapter's inside part writes the record): an adapter's outside part may also write `inside`, only to mark a session ended, and only when the harness skipped its end hook and left evidence that the stop was clean.
- **This amends decision 0013**: `endReason` now means why the session ended, which is the harness's own reason or, where the harness skipped its end hook, a reason Porch read from the harness. Claude Code's idle stop gives `idle`. The idle-stop gap in 0013's Consequences is closed for background sessions.
- The log is read only for a Claude Code session whose record has an inside part that has not ended and has a short id (`data.shortId`), and whose process is not listed running. The line must name that short id and be dated after the later of the record's `lastTurnEnd` and `data.startedAt`, so an earlier stop of a session resumed since does not count. `daemon.log.1` and `daemon.log` are read once per `list` or `observe` call, and only when at least one session needs it. If the log is missing, unreadable, rotated past the line, or the line's format has changed, the session stays `gone`; Porch never guesses `ended`.
- No schema bump. Every existing `endReason` value keeps its meaning, and the field is a free string whose values are listed per harness (`docs/reference/cli-output.md`), so no consumer breaks. A bump would make every consumer move for one new value that only TRV-1158 reads.
- The conformance suite gets a slow case, `idle-stopped`, that waits up to 70 minutes for Claude Code's idle stop. It runs only when asked for (`--slow`, or named with `--case`), because Claude Code's idle timeout is a fixed hour with no setting to shorten it.

Set aside: a new status such as `idle-stopped` (a schema bump for one harness's case); `gone` with a reason field (it mixes died and stopped, which is what this undoes); saving nothing and reading the log on every look (the session would flip back to `gone` once the log loses the line); a new top-level record field written from outside (a second copy of the ended handling).

## Consequences
Sous chef, and any tool on Porch, can tell from one observation whether Claude Code stopped a background session for being idle or the session died, and the answer survives the log rotating. Porch now depends on an undocumented log line; when Claude Code changes it, idle stops show as `gone` again, never as a wrong `ended`, and the `idle-stopped` case would notice on its next run. Interactive Claude Code sessions have no short id and no daemon, so this does not cover them. Pi is not affected. If Claude Code starts running `SessionEnd` when it stops an idle session, the hook marks the record first and the log reading stays as a fallback for older versions. The records folder is now written by an adapter's outside part as well as by `list` and `watch`.
